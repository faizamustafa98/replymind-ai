ReplyMind Feature Catalogue

ReplyMind has 68 features across 11 modules. Must Have features are core MVP functionality, Should Have features are strongly recommended and added as capacity allows, and Nice to Have features are post-MVP stretch goals.

Authentication & Tenant Management
Business owners register with a business name, email, and password; an account and a new isolated tenant record are created automatically. Login uses a JWT token with the tenant_id embedded, so every API call is scoped to the correct business. Password reset via email is supported (reset link expires in 30 minutes). Sessions persist across browser refreshes for up to 7 days via a secure HTTP-only cookie.

Onboarding & Landing
A guided, step-by-step onboarding wizard covers business profile, document upload, channel connection, and auto-reply preference, in that order. Document upload cannot be skipped, since the knowledge base is required for the AI to draft replies. The business profile step captures business name, primary language, and communication tone (professional, casual, or friendly), used to personalize every AI draft. A public marketing/landing page explains ReplyMind's value proposition and pricing, and is accessible without login.

Knowledge Base & Document Management
Owners upload FAQs, menus, catalogues, and policy documents as PDF, DOCX, or TXT files, stored securely in the business's own tenant folder. Multiple documents can be uploaded and are indexed together into one knowledge base. An upload status badge shows Processing, then Ready or Failed. Documents can be deleted (purging their embeddings) or replaced with a new version (old embeddings are removed and replaced). A knowledge base preview lists all documents with status, chunk count, and upload date.

Channel Integration Layer
This is the most critical module, handling inbound message reception and outbound reply delivery across all connected platforms, designed so new channels can be added as independent adapters without modifying existing code. WhatsApp messages arrive via a Meta Cloud API webhook, verified with an HMAC-SHA256 signature; approved replies are sent back via the same API. Email arrives via SendGrid Inbound Parse and is sent via SendGrid SMTP, with replies prefixed "Re:" to keep threads intact. A website chat widget embeds via a single JavaScript snippet, connects over WebSocket, and restores conversation history on page refresh; owners can customize its title and primary color. Every channel implements a common adapter interface. Each inbox message has a deep-link button that opens the original conversation in its native platform. When a conversation falls outside WhatsApp's 24-hour customer-service window, a pre-approved template message re-initiates contact instead of a free-form reply, as Meta requires. If a channel API is unreachable, failed sends are queued for retry with exponential backoff and surfaced to the owner as a delivery failure. Instagram DM integration is planned for a future release, following the same adapter pattern and signature-verification standard as WhatsApp.

Question Classification
Every inbound message is passed through an NLP classifier that determines whether it is genuinely a question, producing a confidence score between 0.0 and 1.0. Messages above a configurable threshold (default 0.60) are routed to the RAG pipeline; messages below it go to a Rejected panel, where the owner can scan, discard, or manually reply, with optional AI assistance available. Each inbox card can show a confidence badge indicating how certain the classifier was.

RAG Pipeline
The AI answering engine. All document embeddings are stamped with the business's tenant_id, and retrieval queries are always tenant-filtered, backed by Row Level Security, making cross-tenant data access architecturally impossible. The incoming question is embedded and the top matching chunks are retrieved from the business's vector store using cosine similarity. If the highest similarity score is below a configured threshold (default 0.72), the AI does not attempt an answer and shows a fallback message like "I do not have enough information to answer this," and the owner replies manually. Before retrieval, recent conversation history is used to rewrite a follow-up message into a standalone, context-aware query (for example, "How much is it?" becomes "What is the price of the blue shirt?"). Retrieved chunks are injected into a prompt that generates a reply in the business's configured tone and language. Every OpenAI API call is logged against the business's monthly usage counter so plan caps can be enforced.

Unified Inbox Interface
All messages from all connected channels appear in a single real-time feed sorted by arrival time, with new messages pushed instantly and an unread-count badge that updates in real time. Each card shows the customer identifier, a channel badge, the question, the AI draft preview, a timestamp, and a Send button. Clicking a card opens the full detail view with the complete draft, channel metadata, and conversation history. The draft is editable inline before sending. Messages can be discarded (soft-deleted, recoverable). The inbox can be filtered by channel and sorted newest-first or oldest-first. A separate answered-history view shows everything already sent, with the final reply, timestamp, and channel.

Auto-Reply Engine
When enabled, high-confidence replies can be sent automatically without owner review. It is an opt-in feature, disabled by default - every draft requires approval until the owner explicitly turns it on. When enabled, messages exceeding a configurable confidence threshold (default 0.92) are sent automatically. Auto-sent messages appear in a dedicated history section, separate from the active inbox, and every auto-sent message records the original question, the reply sent, the confidence score, and the timestamp, stored permanently for review.

AI-Assisted Reply Editor
In the message detail view, the owner can type a natural-language instruction such as "make this more formal" or "shorten this," and the system revises the draft accordingly. This refinement feature uses an OpenAI API key the owner provides in settings (stored encrypted), keeping refinement costs separate from platform RAG costs. Within a single session, the owner can undo the last refinement and revert to the previous draft.

Settings & Configuration
Owners connect and disconnect channels (WhatsApp, email, website widget) from a settings page, with each channel showing Connected, Pending, or Not configured status; credentials are stored encrypted. The minimum RAG confidence score and the auto-reply threshold can each be adjusted independently via sliders. Owners select their preferred AI tone (professional, casual, or friendly) and language. Subscription and billing are managed via Stripe, with hard usage caps enforced at the API layer. A single HTML script tag installs the chat widget. Owners can export all stored conversation and customer-contact data, or permanently delete their business's data.

Analytics
Lightweight, actionable reporting: message volume by channel over the last 7 and 30 days as a bar chart; an AI acceptance rate showing what share of drafts are sent as-is, edited, or discarded; average response time compared to a manual baseline captured during onboarding; and a view of top unanswered question types (low-confidence topics), showing the owner exactly what to upload more documentation about.
